## Core

- [x] **`dusk.md` schema and parser**: `pkg/duskmd`, one entity per file with its prose as the description, derived refs, outbound relations only, and includes that cannot escape the repository ([0004](../adr/0004-dusk-md-convention.md), [0026](../adr/0026-dusk-md-schema.md))
- [x] **Reconciler**: `internal/reconcile`, expanding includes against a tree into the graph, with reading split from storing so a checkout can be validated with no index. `dusk validate` is the local command ([0001](../adr/0001-git-as-source-of-truth.md), [0004](../adr/0004-dusk-md-convention.md))
- [x] **Source boundary**: no VCS type reaches the reconciler, and the local directory source refuses a path that leaves it ([0005](../adr/0005-github-app-and-access-modes.md))
- [x] **GitHub source**: `githubapp.Repository`, reading over the API at a commit resolved once, with a tree cache that needs no invalidation ([0029](../adr/0029-reading-repositories.md))
- [x] **Installation auth**: App assertions and installation tokens, reused until close to expiry ([0005](../adr/0005-github-app-and-access-modes.md))
- [x] **Storage**: `internal/index`, SQLite partitioned by repository and git ref, FTS5 search with ranking and snippets, transactional replace, cheap per-ref garbage collection ([0008](../adr/0008-storage.md))
- [x] **Entity graph**: relations and inbound traversal to a bounded depth, and drift between the declared and observed halves now that plugins supply the observed one ([0007](../adr/0007-entity-schema.md))
- [x] **Poll floor**: periodic sweep of every permitted installation, running whether or not webhooks are configured ([0006](../adr/0006-reconcile-triggering.md))
- [x] **Webhook triggering**: a push reconciles one repository, an installation change triggers a sweep, both answered before the work runs ([0006](../adr/0006-reconcile-triggering.md))
- [x] **Account allowlist**: only the App's own account by default, checked on both the sweep and the delivery ([0030](../adr/0030-account-allowlist.md))
- [x] **Sync observability**: per-repository status with commit, counts, and last error, through the MCP `changes` tool and the homepage's `reads` block
- [x] **`changes` says when**: the tool whose whole purpose is telling a stale answer from a missing one returned commit hashes and counts and **no time at all**, so it could not answer the question it exists for. Every line is now dated, and the **last read and the last attempt are separate facts**: recording a failure against the read time made "failed this morning, last read a week ago" render identically to "read this morning". A confirmed commit counts as a read, because the catalog is provably what git holds as of that moment even though nothing was downloaded. Ingesters are dated the same way, which is the case [0011](../adr/0011-ingester-scheduling.md) creates on purpose and nothing surfaced: a plugin failing since Tuesday now says how old what it is serving is, how many runs in a row have failed and when it tries again, all of which the rotation already knew and none of which it reported. The read time is **derived from the `observed_at` stored with the content**, exactly as [0011](../adr/0011-ingester-scheduling.md) said staleness should be, so it survives a restart rather than reporting that a full catalog has never been read; it moves after an index rebuild because the content was genuinely read again ([0058](../adr/0058-a-read-time-is-a-fact-about-the-read.md))

## Write path

- [x] **Proof tokens**: `pkg/proof`, issued by a read, invalidated by change with a TTL backstop, rejections naming the call that fixes them ([0009](../adr/0009-proof-tokens.md)). A token records **what the write path compares against**, which is a version for an entity and a content hash for a note: search joined a hit against entities alone, so every note it returned came back with an empty version and the token that advertised "pass it to `note`" could never satisfy one. Not a race, and repeating the search reproduced it exactly.
  A rejection also **names a call the surface takes**, which is a second fact from the ref rather than derivable from it: the code phrased every fix as `get(<ref>)`, so a refused note write named a call `get` refuses outright and `kinds` and `page` were told to take a path neither accepts. The caller now names the read, and `note(id:)` on its own reads that one note, because the call an error names has to exist
- [x] **Rendering `dusk.md`**: `pkg/duskmd`, frontmatter rewritten and prose left byte-identical, so a write cannot disturb what somebody wrote ([0026](../adr/0026-dusk-md-schema.md))
- [x] **Committing over the API**: `githubapp.CommitFile`, one file per commit, presenting the blob sha so a raced write collides instead of overwriting ([0010](../adr/0010-mcp-surface.md), [0029](../adr/0029-reading-repositories.md))
- [x] **`declare`**: `internal/write`, routing to the file that declares an entity, rewriting only its frontmatter, and committing to the default branch. Creating places the file under an `include` glob and refuses when none would reach it ([0010](../adr/0010-mcp-surface.md)). **Placing is `catalogfs.Place`, beside the matcher it has to agree with**, and every path it produces is checked against `Match` before it is returned: the write path had its own substitution that knew nothing of `**`, so a repository whose every entity sits under `entities/**/*.md` could be read and not written to. Its other half was quieter, and was found by the test written for the first: a wildcard-free `include` names one file, and substituting into it put every new entity in that one
- [x] **Write containment**: writes reach only repositories a sweep has seen *and* that already contain a `dusk.md`. Dusk never creates one, because that file is how a repository consents ([0004](../adr/0004-dusk-md-convention.md))
- [x] **Read mode**: a write returns the change it would have made, as a unified diff against the repository and path it would have written, rather than a 403 an agent can do nothing with. One gate, `write.land`, so no write path can forget it, and the proof token is still required because the diff is against the file as it stands. The browser's one write says the same thing rather than reporting a success it did not have ([0005](../adr/0005-github-app-and-access-modes.md), [0010](../adr/0010-mcp-surface.md), [0052](../adr/0052-a-write-that-cannot-land.md))
- [x] **Notes**: a note is its own file, discovered like any other, written to the config repository's `.dusk/` ([0031](../adr/0031-notes-are-files.md)). `search` covers entities and notes together, and `get` returns the notes attached to what it answers about
- [x] **Ideas**: a note of kind `idea`, which is a note that is **work** rather than knowledge. Two things follow. A note may attach to **nothing**, because an idea is often not about anything in the catalog yet and refusing it would make the ones worth capturing the ones that cannot be. And a note carries a **status**: open, done or dropped, with empty meaning open so nothing written earlier reads as finished. `note` reads as well as writes, narrowed by kind, status and ref, and the read is what yields the token that closes one, the same shape `page` has. A closed note is still shown, because "I already had that idea and dropped it" is the answer somebody most needs and least expects
- [x] **Note dedup**: the path is the body's hash, so writing the same note again is a file read that answers with the id of the one that exists rather than the 422 GitHub used to give. Nothing is merged into it, because [0009](../adr/0009-proof-tokens.md) exempts a create from the proof gate only on the grounds that a create cannot overwrite. A near duplicate is **written and named**, never refused, on [0033](../adr/0033-graph-integrity.md)'s reasoning that a catalog still being adopted must not be argued with, and nearness is word overlap over FTS5 candidates because a bm25 threshold means nothing between queries ([0010](../adr/0010-mcp-surface.md), [0053](../adr/0053-note-dedup.md))
- [x] **Vocabulary**: one `kinds` tool that reads and mints, because the read is what issues the proof a mint needs and a vocabulary you have not read is how `svc` appears beside `service`. Most of it is **derived**, counted out of the rows the catalog is already read from, so there is no registry to keep in step; minting adds only what counting cannot reach, a **role** and **aliases**. Every role has a consequence, so nothing decorative can be minted: `reference` quiets an entity kind in drift, which is what [0045](../adr/0045-drift-is-a-maintenance-queue.md) wanted and was blocked on an interface for, and a note role decides rank. A near match is **warned and never refused**, in the answer to the call that created it, because refusing would delete [0007](../adr/0007-entity-schema.md)'s open vocabulary; the one refusal is minting a name the vocabulary already has in another spelling, which the answer redirects to an alias ([0007](../adr/0007-entity-schema.md), [0010](../adr/0010-mcp-surface.md), [0048](../adr/0048-the-kind-vocabulary.md)). Documented in [docs/kinds.md](kinds.md)
- [x] **Correcting a kind**: minting one the vocabulary has, spelled the same way, sets its role and adds its aliases rather than being refused. That refusal was checked against the *derived* vocabulary, so it caught the case minting exists for: a kind nobody minted is already in the list under the default role, which made the one role worth correcting the one that could not be. It also refused its own advice, since "mint `service` with `Service` in its aliases" needed minting a name that exists. The read that authorizes it is the one that prints the current role, so nothing is corrected blind, and a mint that would change nothing writes nothing ([0048](../adr/0048-the-kind-vocabulary.md), [0054](../adr/0054-correcting-a-kinds-role.md))
- [x] **Note ranking by kind**: a note's kind is its rank, through a **role** rather than a number, so a minted kind ranks from the moment it exists rather than sitting at the bottom of a hard-coded table. `warning`, `knowledge` and `work`, and the seven seeded kinds split into them with no awkward cases. A gotcha reaches the top of an entity page with nobody pinning it, which frees pinning to mean "this one specifically" again, and it is what [0014](../adr/0014-agent-context-injection.md)'s context budget assumes it means. In search a work note ranks below every other hit and by relevance within that group, so a todo never outranks a gotcha or an entity. `duskmd.Working` stops being a second hand-maintained list, because whether a note can be closed is the same fact as where it ranks ([0031](../adr/0031-notes-are-files.md), [0049](../adr/0049-a-notes-kind-is-its-rank.md))
- [x] **`.dusk/` holds catalog content and Dusk's own configuration**: `home.md` and `kinds.md` are named once in `catalogfs` and skipped by a reconcile. Found rather than introduced: a repository declaring a portal page parsed it as an entity and failed its whole reconcile ([0048](../adr/0048-the-kind-vocabulary.md))

## MCP

- [x] **Read tools**: `search`, `get`, `neighbors`, `changes`, `drift` and `dusk_context` over streamable HTTP at `/mcp`, answering in markdown ([0010](../adr/0010-mcp-surface.md))
- [x] **Agent surface access**: bearer token, or an explicit trusted-network mode, and off until one of them says. Never a default ([0012](../adr/0012-viewing-auth.md))
- [x] **A kind narrows the search query**: `search(query, kind)` asks the index for that kind rather than dropping the wrong ones from a page the limit already cut. Applied afterwards it answered "Nothing in the catalog matches" for a kind whose matches sat past the window, which is the one answer this surface must never invent, because it teaches agents that absence means undocumented. Fixed in the index, so the MCP tool, the homepage's entity blocks and `GET /api/search` are all fixed by one change ([0059](../adr/0059-what-a-list-may-not-leave-unsaid.md))
- [x] **A search says how many matched**: "3 of 12 result(s), the highest ranked. Raise `limit` for the rest", and an empty answer repeats the kind it looked for. The count is exact and costs nothing, because SQLite computes it in the same statement over the rows the match produced and before the limit applies. `GET /api/search` returns it as `total` ([0059](../adr/0059-what-a-list-may-not-leave-unsaid.md))
- [x] **Notes are bounded in bytes and named rather than cut**: `note` said nothing about the twenty-five runbooks it left out of thirty-five, and `get` on a heavily annotated entity was 78,720 characters of notes printed whole. Both now say how many matched, print whole while they fit a byte budget, and name the rest by kind, id and opening line, which is the id to pass back. Nothing is dropped, so a note an agent knows exists is one call away. `get(titles: true)` names every attached note without printing one. The read's default limit rises above what the budget could ever name, so the budget decides what is shown rather than a row count nobody sees hit ([0031](../adr/0031-notes-are-files.md), [0050](../adr/0050-what-the-context-budget-buys-first.md), [0059](../adr/0059-what-a-list-may-not-leave-unsaid.md))
- [x] **A related ref carries the name of what it points at**: `get` and `neighbors` resolve every ref they list in one query, so choosing which of twenty-two related things to open no longer costs twenty-two calls. A ref nothing declares still renders, because that is drift rather than an error. The **status** of a related thing is deliberately not shown: "In Progress" is a board's concept, and Dusk guessing which attribute carries it would be re-deriving what a plugin normalized ([0018](../adr/0018-normalization-at-the-edge.md), [0033](../adr/0033-graph-integrity.md), [0059](../adr/0059-what-a-list-may-not-leave-unsaid.md))
- [x] **An entity is findable by part of its name**: FTS5 matches whole words with a prefix on the last, and infrastructure names are compounds, so a search for three letters returned a person's surname and not the host whose name ends with them. A search now also finds entities whose `name` holds every word of the query, ranked below a word hit and above a work note. Prose is unchanged, because a substring over prose finds "cat" in "concatenate". Words under three characters are left to the prefix match ([0060](../adr/0060-finding-an-entity-by-part-of-its-name.md))
- [x] **A token names the write it authorizes**: every read closed with the same sentence offering the token to `declare` or `note`, which is false on four of them. A page token is spent on `page` and nothing else; a note token on `note`, since `declare` takes an entity ref and a note's id is a path; a walk's token covers the one ref it read and not the page of refs it named; and an empty search offered to write "any of the above" over nothing at all. The read now names the write, which is what `kinds` had been doing privately with its own "Pass it with `mint`" line, and that privacy is why nobody noticed the rest were wrong. Deriving it from the token's origin was the close call and lost for [0009](../adr/0009-proof-tokens.md)'s own reason about the call a rejection names: the offer depends on what the read returned, not on which read ran, and a wrong derivation is invisible. A note read that matched nothing now issues no token and says a new note needs none ([0061](../adr/0061-a-token-names-the-write-it-authorizes.md))
- [x] **A plugin page says how each action is invoked**: `get plugin:name` closed with "run one naming this plugin and no ref" whatever it had just listed, which is wrong for every entity-scoped action and is a call `invoke` refuses by name for applying to a kind. The page stamped one sentence over both halves while the information to tell them apart was already on each action. It now says it per action, grouped by what they apply to, and a plugin with nothing to run says which kind of nothing: declaring none is not the same as declaring some that nobody enabled, and only the second is fixable by whoever is reading ([0015](../adr/0015-plugin-actions-and-events.md), [0041](../adr/0041-plugins-reach-agents-as-actions.md))
- [x] **A note hit prints its path once**: [0031](../adr/0031-notes-are-files.md) gives a note no title, and the search renderer fell back to the ref for the name and then printed the ref beside it, so every note hit carried its path twice. A hit with a title still renders both, because a title is a name and a ref is an identifier; one without renders the ref alone
- [x] **A version is abbreviated only when it is a commit**: provenance carries whatever identifies the version something was read at, and `short` took the first seven characters of all of it, so an observation read `at refs/du`. That names nothing and reads as a truncated sha, which is worse than the whole ref: it looks like an identifier somebody could go and find. Only a hex string is shortened now
- [x] **An attribute is rendered by its kind**: attributes are arbitrary JSON and were formatted with `%s` against a `structpb` value, so every number an operator declared printed as `%!s(float64=125)` and a map printed as a Go map dump. A scalar is now prose and anything composite is the JSON it already is, which is the same reasoning that made a plugin's `detail` render as JSON: a list of multi-word strings printed the Go way is `[Backlog To Do In Progress]`, and that is a different answer rather than an uglier one
- [x] **A read resolves its subject**: `neighbors` never looked up the ref it was asked to walk from, so a ref nothing declares answered "No relations are declared for it", which is what a declared leaf answers. An agent that mistyped a ref, or one checking blast radius before a teardown, reads that as "nothing depends on this" and acts on it: the same fabricated absence [0059](../adr/0059-what-a-list-may-not-leave-unsaid.md) fixed in the query, reached from the other end. It now answers the way `get` already did and names `search`. What points at that ref is still listed under the absence, because an entity removed while other repositories still declare relations to it is [0033](../adr/0033-graph-integrity.md)'s drift and is exactly what a teardown has to look at ([0059](../adr/0059-what-a-list-may-not-leave-unsaid.md))
- [~] **Write tools**: `declare`, `note`, `page` and `kinds` are built, and every read with something to write against issues the proof token they need. `relate` and `push` are not ([0010](../adr/0010-mcp-surface.md))
- [x] **Curating the homepage**: `page` reads the declared page, or the default written out when there is none, and rewrites it against a proof token. **A repository that has never declared one can now declare its first**: a create was gated on a `search` token, and no search can name a file, so the only path to a first page was the browser or a hand-written commit ([0009](../adr/0009-proof-tokens.md)). One tool for both halves, because the read is what authorizes the write and a separate read tool would look optional. The page is parsed before it is committed, so a bad block is a failed call rather than a blank homepage ([0013](../adr/0013-layout-and-pages.md))
- [~] **Context injection**: the MCP `instructions` field is served and `dusk_context` answers with the estate. The client hook is not built ([0014](../adr/0014-agent-context-injection.md))
- [x] **Pinned notes reach agent context**: what the operator pinned arrives before the session asks, ranked above the inventory it displaces, because a ref left out is one `search` away and a gotcha left out is reachable by nothing. Sections are paid in priority order and printed in reading order, and **nothing is dropped without being named**: a note that does not fit is listed by kind, id and opening line, a kind that does not fit prints its count, and every section says how many entries it left out on room reserved before anything is spent. A share cap keeps forty pinned notes from erasing the inventory. Relevance to the repository being worked in orders the pinned set and does not widen it, so an unpinned note still stays out ([0014](../adr/0014-agent-context-injection.md), [0050](../adr/0050-what-the-context-budget-buys-first.md)). It also fixed a half that had never worked: the entities a repository declares were matched against provenance, which records the file a declaration came from and never the repository, so that list read as empty everywhere
- [x] **The context budget is spent on what it prints**: driven against a live catalog, the first call a session makes answered in 900 bytes of 8000, because a section granted room for whole notes printed one-line shorts and the difference was never reclaimed, and because a cap of half the budget does not bind when there are four sections. Spend is now measured by rendering, the share binds on what is left when a section's turn comes, and the same catalog answers in 6949. Four defects visible in that one answer went with it: the inventory was ordered alphabetically and so elided `service` from a service catalog, and now ranks by [0048](../adr/0048-the-kind-vocabulary.md)'s role with infrastructure above reference; an overflow line named nothing it dropped and now names it; a fragment printed with no heading, because the heading was charged against a budget that can be smaller than itself and is now reserved beside the overflow line; and a ref reaching the index from two sources was listed twice. The orientation also says, in one sentence, that the catalog acts: nothing in it mentioned actions or `invoke`, so an agent that never happened to `get` an acting entity never learned a plugin was installed ([0057](../adr/0057-charged-for-what-was-printed.md))

## UI

- [x] **HTTP API**: search, entities and their dependents, overview, status, drift, integrity, home, viewer, diff, and the plugin routes. The UI is an ordinary client of it with no privileged path
- [x] **React app**: React 19 and TypeScript, built by Vite, embedded via `go:embed`, dark only, Dracula Pro
- [x] **Browser auth**: a session cookie exchanged for the same token agents present, so one policy covers both surfaces
- [x] **Pages**: the homepage is `.dusk/home.md` in the config repository, an ordered list of typed blocks, each a query rather than a widget. What is declared is the whole page, so removing a default block is deleting a line. Entities blocks take the query grammar including `related:` in either direction and sorting by any attribute, which is what makes "the latest three flights" a block. Blocks resolve server side, so a page is one request rather than one per block ([0013](../adr/0013-layout-and-pages.md), [0035](../adr/0035-blocks-resolve-server-side.md)). Documented in [docs/pages.md](pages.md)
- [x] **PR previews**: the catalog rendered at an unmerged ref, a semantic diff, and one comment edited in place ([0001](../adr/0001-git-as-source-of-truth.md), [0037](../adr/0037-pull-request-previews.md))
- [x] **Viewing auth**: sign in with GitHub using the App Dusk registered, visibility derived from repository access, observed entities hidden unless allowed ([0012](../adr/0012-viewing-auth.md), [0036](../adr/0036-deriving-what-a-viewer-sees.md))
- [x] **A count is of what the viewer can see**: drift, integrity and the kind counts were the only reads a signed-in person saw unfiltered, and each named refs, repositories and file paths they could not otherwise open. A restricted viewer's catalog is now a sub-catalog: every read that cannot be narrowed afterwards takes an `index.Visibility` and is computed as though the half they cannot see does not exist. **A list is filtered where it is rendered, a count where it is computed**, because a duplicate is a count of copies and narrowing the answer would report one while naming the repository holding the copy that made it a duplicate. The counting question had two defensible answers and the rejected one is the interesting half: a total over the estate leaks its size, per-kind counts leak its shape, and the difference between a count and the list under it is the hidden count exactly. Making the argument required rather than optional is what stops a fourth aggregate read shipping unfiltered. Under the default `DUSK_OBSERVED_VISIBLE_TO_ALL=false` a restricted viewer sees no observation, so nothing is watched and [0038](../adr/0038-what-drift-may-say.md) makes drift empty for them, which is correct and will read as broken ([0051](../adr/0051-a-count-is-of-what-the-viewer-can-see.md))
- [x] **Admin**: the plugins page installs, updates, uninstalls and configures, with sensitive fields write-only and a marker saying which are set so an empty box is not mistaken for an empty value ([0023](../adr/0023-plugin-configuration.md)). It is also where an action is enabled, where a plugin's own views mount, where its output is read, and where what has been run is listed
- [x] **Actions in the browser**: a card per enabled action, a form rendered from its JSON Schema, a preview button, and a confirmation for anything destructive that carries the preview or says there is none. Nothing in it knows about any plugin. The entity read issues the proof token the action presents, so a page left open while something changed refuses rather than acting on what is no longer true ([0009](../adr/0009-proof-tokens.md))
- [~] **Responsive layouts**: mobile first, one breakpoint, wide content scrolls inside its own container. Nothing yet does the table-to-card or graph-to-list transform, because neither exists ([0025](../adr/0025-responsive-ui.md))
- [~] **Viewport matrix tests**: run by hand at 320, 390, 430, 768, 1024 and 1440 against a real catalog, on the landing and entity pages. No overflow and no touch target under 44px at any of them. Not automated, so nothing stops the next change regressing it ([0025](../adr/0025-responsive-ui.md))

## Plugins

- [x] **One transport**: gRPC over a host-provided unix socket, and no second way in ([0039](../adr/0039-one-plugin-transport.md))
- [x] **`GetAsset` RPC**: streams a plugin's JavaScript in chunks, which Dusk hashes and serves content addressed at `/plugin-assets/{plugin}/{sha}.js` from its own origin. Immutable caching is safe there because a different asset has a different URL. Proven by `dusk-plugin-airtrail`
- [x] **Plugin UI**: a plugin ships a custom element, not a React component, so it shares no runtime with Dusk and brings its own rendering. Styling crosses the shadow boundary through CSS custom properties, which inherit where classes do not ([0020](../adr/0020-plugin-ui.md))
- [x] **Scheduler**: intervals, concurrency cap, exponential backoff and a circuit breaker, never delete on failure ([0011](../adr/0011-ingester-scheduling.md))
- [x] **Shared per-source budget**: a plugin names the config fields identifying its upstream system, and every configuration resolving to the same values queues behind the others rather than each assuming it has the whole quota. Declaring no key fields means no sharing, so a plugin that has not thought about it is not throttled by accident. A run that cannot get a turn is **deferred, never failed**: counting a deferral as a failure would let a busy source trip the circuit breaker meant for a broken one. Dusk meters runs rather than requests, because what a plugin does upstream happens inside its own process ([0011](../adr/0011-ingester-scheduling.md))
- [x] **Kubernetes moved out of core**: `internal/ingest/kubernetes.go`, `DUSK_KUBERNETES` and the cluster configuration are gone, and `k8s.io/client-go` with them. Core now carries no ingester at all: the scheduler is constructed empty and plugins join it as they start, so there is no in-tree path an observation can take ([0034](../adr/0034-ingesters-in-tree-first.md), [0040](../adr/0040-core-and-plugins.md))
- [x] **Kubernetes plugin**: `NerdsWhoFish/dusk-plugin-kubernetes` serves `PluginService` over a host-provided unix socket, observes a real cluster, and ports the namespace and plumbing filters intact

A contribution sets a spec or an element, never both. One declaration is a button on the entity page, an `invoke` over MCP, and the approval gate. Routing is by **which plugin observed the entity**, and an action runs against the configuration of the instance that saw it, so a plugin watching two clusters acts on the right one. A mutating action asks its instance to observe again rather than leaving the catalog showing what was true before
- [x] **Host runtime**: a plugin is exec'd on a host-provided unix socket, answers `Describe`, and joins the rotation as an ordinary `ingest.Ingester`, so scheduling, backoff and the never-delete rule are not reimplemented for it
- [x] **Marketplace, install and update**: `dusk-plugin-*` in allowlisted orgs, checksum verified before anything runs, cached on disk so a restart needs no network, updates applied only when a human says ([0042](../adr/0042-installing-plugins.md))

A field submitted empty keeps what is stored, because a write-only form submits empty when it was not retyped; an explicit null forgets it. - [x] **Plugin capability over MCP**: one `invoke` tool, and discovery folded into `get`, so a tenth plugin adds no tools. An agent reads an entity and the answer already says what can be done to it, with which class, whether it needs confirming, and which read yields the proof token ([0041](../adr/0041-plugins-reach-agents-as-actions.md))
- [x] **Configuring a plugin over MCP**: a `configure` tool, merging over what is there rather than replacing it, so setting one field does not clear the rest. Sensitive fields are **refused by name**, not accepted and dropped. ADR-0041 said this would ride on `declare`, on the premise that non-sensitive configuration was already frontmatter in the config repository; it never was, and [0043](../adr/0043-plugin-configuration-stays-out-of-git.md) records why it stays where it is ([0041](../adr/0041-plugins-reach-agents-as-actions.md), [0023](../adr/0023-plugin-configuration.md))
- [x] **A plugin can ask the human a question**: an action whose input is a judgement rather than a lookup can insist a person supplied it, instead of trusting that the calling agent did not invent it. The question is **returned, not called**: `InvokeResponse.elicit` ends the turn and Dusk invokes again with the answer, which is what lets a surface with nobody attached reply `unsupported` rather than hanging. That keeps one declaration working from an agent, the UI and a schedule ([0041](../adr/0041-plugins-reach-agents-as-actions.md)), and keeps `Invoke` unary so [0039](../adr/0039-one-plugin-transport.md) is not re-decided by making the contract's central RPC streaming. Additive, so the plugins written before it are untouched. Bounded at four turns, because a question is a loop waiting to happen. **The browser answers too**, by the same mechanism one level up: nothing can hold an HTTP request open while somebody reads a form, so a resumable caller gets the question back as its result and answering invokes the same action again. The form is rendered from the plugin's schema by the code that already renders action parameters. Dusk holds nothing between the two requests, because the plugin's token carries what it needs to continue. What still cannot ask is a **chained step**, since the caller is already holding the result of the action that started the chain. One ask is bounded in time as well as in number: a client that declares the capability and then does not answer left the invocation hung until its transport dropped, which the turn count did nothing about ([0046](../adr/0046-plugins-can-ask.md))
- [x] **A plugin can be read like an entity**: `get plugin:name` lists what a plugin can be asked to do. An action about the plugin rather than about one thing appears on no entity, so [0041](../adr/0041-plugins-reach-agents-as-actions.md)'s promise that a capability reaches an agent through the tools that already exist held only for the entity-scoped half. Found by driving a plugin whose every action is plugin-scoped: it was invokable and undiscoverable at the same time
- [x] **Structured output survives the trip**: a plugin's `detail` is arbitrary structure, and Go's default formatting turned it into `map[k:v]`, which is neither JSON nor prose. Scalars stay bare and anything nested is rendered as JSON, because a plugin whose whole answer is structured data was unreadable
- [x] **Plugin health reaches an agent**: `changes` answers "how much should I trust this", and an observation nothing refreshes is a stale answer with no marker on it, so a failing plugin belongs in that answer rather than only on a page
- [x] **A plugin that dies is started again**: documented in [docs/plugins.md](plugins.md). The process exiting is the trigger, so nothing polls and nothing waits for the next call to discover it. Backoff doubles from a second to a cap of a minute and gives up after eight attempts, because a crash loop must be neither a hot loop nor an infinite one, and a process that stayed up for a minute resets the count so a plugin that has served for a week is not given up on the second time it ever crashes. The **load-bearing rule is that a restart is never observable as an empty ingest**: an observation is complete by contract, so a dead or restarting process answers every call with an error naming the exit, checked before the stream is opened and again when it ends. A caller interrupted mid-action is told the process went away, and a mutating one is told its outcome is **not known**, because what could have said whether it landed is what died. `failed` is a state with a way out: `Restart` on the plugin's page, which is the only way out, since configuring a plugin needs it running. What it printed as it died survives into the process that replaces it ([0011](../adr/0011-ingester-scheduling.md), [0039](../adr/0039-one-plugin-transport.md), [0055](../adr/0055-supervising-plugin-processes.md))
- [x] **Each Dusk binds its own socket directory**: sockets are named per plugin id, so two Dusks on one machine each removed the other's on start and on stop. Fixed here rather than recorded, because a supervisor turns a collision at install and boot into one at any moment: restarting is unlinking and rebinding. [0044](../adr/0044-plugins-keep-the-socket-directory.md) is untouched, having rejected a directory per *plugin* as theatre under one user and said nothing about two hosts sharing a namespace

### Plugins composing, through Dusk

One plugin's work often wants another's: create a DNS record, then restart the workload that serves it. The sockets make direct calls physically possible, and every one of these items exists because they should not be made that way.

A plugin calling another directly would collapse the trust boundary, since approving one plugin would silently grant it everything its neighbours can do. It would create an undeclared dependency graph with no versioning and a silent skip when the other plugin is absent, which is the failure mode [0011](../adr/0011-ingester-scheduling.md) exists to prevent. And it would be invisible to the catalog, which is self-defeating for a product whose claim is that it records what happened.

Dusk is the orchestrator. An agent already composes actions this way through `invoke`, so what follows is about making it declarative, guarded and recorded rather than possible.

- [x] **Plugins cannot serve each other**: Dusk mints a token per start, presents it on every call, and a plugin refuses anything without it. Not a defence against a hostile plugin, which already runs with Dusk's permissions ([0042](../adr/0042-installing-plugins.md)); it stops plugins coupling to each other by accident
- [x] **Declared composition**: an action declares what may follow it, by ref rather than by reaching for a socket, and an invocation returns the concrete steps once it knows them. Dusk resolves, approves and invokes each. **Only an action the descriptor already declared is accepted**, because otherwise approving a chain would mean approving whatever the plugin appended once it was running
- [x] **Approval across a chain**: approval is the strongest `ActionClass` anywhere in the declared chain, so a harmless first step leading to a destructive one is confirmed like the destructive one ([0015](../adr/0015-plugin-actions-and-events.md))
- [x] **A missing link is loud**: a step nothing serves, or one whose action is not enabled, is reported as a failed step naming what is absent, and the chain stops there rather than running the rest of a sequence whose earlier step did not happen
- [x] **A chain can end in a plugin-scoped action**: a step naming no ref used to inherit the parent's, so an action applying to no kind was looked up against an entity and refused with "nothing offers this on a widget". Nothing could compose onto an action about the plugin rather than about one thing, which is most of what a chain is for. A step now inherits the parent's ref only when the declaring plugin says the action applies to a kind. Found by the ADR plugin, which abandoned composition over it
- [x] **Events span the chain**: every invocation in one composition carries the same chain id, so what actually ran is answerable afterwards rather than being adjacent records
- [x] **Stronger isolation than a shared token, decided against**: a socketpair on an inherited descriptor would remove the path, and would re-decide [0039](../adr/0039-one-plugin-transport.md) by the back door, because gRPC on a descriptor is comfortable only in Go and a socket address is what every language handles. Per-plugin directories change nothing under one user, and unlinking after connect turns a reconnect into a permanent failure. The token stays the boundary ([0044](../adr/0044-plugins-keep-the-socket-directory.md))
- [x] **Shared plugin release workflow**: GoReleaser with conventional-commit notes, living once in `NerdsWhoFish/.github` and called by every plugin rather than copied ([0021](../adr/0021-release-tooling.md))

GitHub is not on this list. It is core and stays there: git is the source of truth, so GitHub is substrate rather than a source among sources ([0040](../adr/0040-core-and-plugins.md)).

## Declined

Not deferred, and not forgotten. The operator has decided against these, and they are recorded so the next reader does not treat them as pending work.

- **Durable events.** [0015](../adr/0015-plugin-actions-and-events.md) left room for an optional time-series exporter and nothing will export. Events stay a bounded in-memory buffer answering "what just happened", and Dusk has no audit trail of its own. The consequence to accept is that nothing can answer who invoked what last week, which matters more now that plugins act rather than only observe.
- **Proposal mode.** A per-session branch and a pull request, from [0005](../adr/0005-github-app-and-access-modes.md). It was granted `contents: read` and so could never commit, and since [0052](../adr/0052-a-write-that-cannot-land.md) a write in it returns the proposed diff exactly as read mode does. There is nothing it offers that read mode does not.
- **Authorization derived from repository access.** [0012](../adr/0012-viewing-auth.md) deferred it until there was a second reader, and there is still one. The MCP surface therefore authenticates without authorizing: any bearer token reads the whole catalog, and the write half of the API asks only whether a caller is signed in, never who they are. The Known gaps below spell out the edges that follow from this; they are the price of the decision rather than bugs waiting to be fixed.

## Known gaps

- **The conformance half of [0064](../adr/0064-a-declared-view-mounts-where-a-result-set-comes-from.md) is owed to the SDK.** `validateUI` in `dusk-plugin-sdk` needs one rule: a contribution setting `spec` in the plugin slot is a violation, because a declared view draws a result set and that page has none. Until it lands the refusal happens only in Dusk, so an author sees it once the plugin is installed rather than while writing it, which is later than the whole point of the rule. The ADR states the change and the message.

- **A declared view mounted on a page can name fields the block's query never returns.** The spec was written against the entities the plugin emits and the query is the operator's, so the two can disagree, and the result is a table of "not set" rather than an error. Nothing checks it, because Dusk would have to know which attributes a plugin puts on which kind, which is what [0018](../adr/0018-normalization-at-the-edge.md) keeps out of core ([0064](../adr/0064-a-declared-view-mounts-where-a-result-set-comes-from.md)).

- **A contribution whose asset was not fetched is dropped in silence.** `Views` skips an element with no asset, on the grounds that mounting a tag nothing defines renders an empty box with no explanation. Dropping it renders nothing with no explanation either, which is the same defect [0064](../adr/0064-a-declared-view-mounts-where-a-result-set-comes-from.md) fixed for a declared view in the plugin slot, and the `Problem` field is now there to carry it. Left alone because a failed asset fetch fails the whole start today, so it is unreachable rather than merely unhandled.

- **The context reserves room for overflow lines it may never print.** Every section with entries has its heading and its worst-case overflow line set aside before anything is spent, which is what makes "nothing is dropped without being named" a property of the assembly rather than a promise each section has to keep. A section that drops nothing pays for the line anyway, so a few hundred bytes of the budget are held against sentences that do not exist. It is the same waste [0057](../adr/0057-charged-for-what-was-printed.md) exists to fix, one order of magnitude smaller, and deferred rather than missed.

- **`List` returns a ref once per source, and `dusk_context` deduplicates it.** Two repositories declaring the same entity, and an ingester observing what one of them declares, are both real states, and returning every row is what lets `integrity` report the first of them ([0033](../adr/0033-graph-integrity.md)). Nothing else currently renders a list of entities where the duplicate would show, so the deduplication sits in the one caller that needs it. The second caller to need it will copy it rather than find it, and that is the moment to decide whether the index should offer a deduplicated read.

- **Only the notes half of `get` is bounded.** An entity with a thousand relations still answers with a thousand lines. Nothing has hit it, and a second budget with no case behind it is speculative machinery, so it is recorded rather than built ([0059](../adr/0059-what-a-list-may-not-leave-unsaid.md)).

- **Whether a note is open is spelled in two languages and three places.** `internal/index` owns it as SQL, `status IN ('open', '')`, once in the predicate builder and once in the filter switch, and `renderNote` spells the inverse in Go to decide whether to print a status mark. `pkg/duskmd` owns the constants and not the rule, so nothing stops the two disagreeing about what an empty status means, which is the case the rule exists for. The fix is a predicate in `duskmd` with the index building its `IN` list from the same set ([0031](../adr/0031-notes-are-files.md), [0049](../adr/0049-a-notes-kind-is-its-rank.md)).

- **Whether an action is enabled is filtered in three places.** `internal/mcp` narrows a list to the enabled ones, `dusk_context` asks whether any exist at all, and `internal/plugin/invoke.go` refuses a disabled one at three separate gates. [0015](../adr/0015-plugin-actions-and-events.md) makes enabling a deliberate act, which makes this a rule rather than a field read, and the package that owns the type is where the predicate belongs. Nothing disagrees today; a fourth caller reading the field directly is how it starts.

- **The short form of a note is written twice.** `dusk_context` builds "kind · id: opening line" inline while `nameNote` builds it for `get` and `note`, so the two can drift into disagreeing about what a named note looks like. One function, called from both, is the fix ([0050](../adr/0050-what-the-context-budget-buys-first.md), [0059](../adr/0059-what-a-list-may-not-leave-unsaid.md)).

- **A full-text hit is one row per scope, so an entity both declared and observed is returned twice and counted twice.** The count [0059](../adr/0059-what-a-list-may-not-leave-unsaid.md) prints is therefore of rows rather than of things. The name half of a search does resolve to one hit per ref, the way `Get` does, so only the full-text half is affected. Deduplicating it means choosing which copy's version the proof token records, and `Get` and `Locate` already order that differently, so it wants deciding rather than patching ([0033](../adr/0033-graph-integrity.md), [0060](../adr/0060-finding-an-entity-by-part-of-its-name.md)).

- **The browser still says nothing about a cut search.** `GET /api/search` returns `total`, and the landing page renders the results without it, so a person sees twenty-five of four hundred exactly as the agent surface used to ([0059](../adr/0059-what-a-list-may-not-leave-unsaid.md)).

- **A hit found by its name has no snippet**, because `snippet()` quotes a full-text match and there is none inside prose to quote. It renders as its title and ref alone, thinner than the hits above it ([0060](../adr/0060-finding-an-entity-by-part-of-its-name.md)).

- **The name half of a search scans.** `instr` cannot use an index, so it reads the entities table on every search, which [0008](../adr/0008-storage.md) sized for thousands of entities rather than millions. A second trigram index over identity is the upgrade path and is not built ([0060](../adr/0060-finding-an-entity-by-part-of-its-name.md)).

- **A killed Dusk leaves its socket directory behind.** Each one mints a directory under `SocketDir` and removes it on shutdown, so an unclean exit leaks one holding a dead socket. Nothing sweeps them, because a sweep cannot tell a leaked directory from a live Dusk's, and removing the wrong one is the bug the directory exists to fix ([0055](../adr/0055-supervising-plugin-processes.md)).

- **Restarting a plugin hides the reason it needed restarting.** A plugin that leaks and dies every hour reads as running with a count beside it, and nothing escalates on that count. Visibility is the whole mitigation ([0055](../adr/0055-supervising-plugin-processes.md)).

- **A mutating action interrupted by its plugin dying has an unknowable outcome**, and the event records it as failed because `EventStatus` has no word for unknown. The message says so; anything retrying on the record rather than the message can apply an effect twice ([0055](../adr/0055-supervising-plugin-processes.md)).

- **Two backoff curves govern one plugin.** The ingest breaker paces one that is up and failing every observation, the supervisor paces one that is not up. Deliberately separate, because one is about an upstream budget and the other about exec, and a reader will reasonably expect them to be one thing.

- **A clean shutdown part way through an observation reads as a failed run.** The liveness check at the end of the stream cannot tell that from a crash. Safe in the direction that matters, since a failed run keeps what the catalog had ([0011](../adr/0011-ingester-scheduling.md)).

- Catalog content is fed to agents with no trust boundary of its own. [ADR-0030](../adr/0030-account-allowlist.md) narrows *who* can reach that path but does nothing about a compromised repository inside an allowed account.
- Two repositories declaring the same entity is **reported but not resolved** ([0033](../adr/0033-graph-integrity.md)). `integrity` names both declarations; `Get` still returns whichever sorts first until a human picks.
- The MCP surface authenticates but does not authorize. A bearer token answers "may you read", not "what may you read", so any agent holding one reads the whole catalog ([0012](../adr/0012-viewing-auth.md)).
- Nothing keeps the chart in step with the application. A release adding a required value ships an image no published chart can deploy until someone notices ([0024](../adr/0024-charts-publishes-charts.md)).
- Access mode is fixed at registration. Changing it means editing the App's permissions on GitHub, which installations must then approve.

- A note's refs and a relation's target are still unchecked at write time, deliberately, because the target may live in a repository Dusk cannot see. Both are now **reported** by `integrity` instead of failing silently ([0033](../adr/0033-graph-integrity.md)).
- Integrity reports every unresolvable ref, and in a partially adopted catalog most of them are legitimate. Nothing distinguishes "typo" from "not adopted yet".
- Drift matches a declaration to an observation by ref, or through an explicit `observed_as` when the two are named differently. Nothing infers the mapping. Since [0056](../adr/0056-coverage-is-a-namespace.md) an estate that uses its own names and has not written them shows those entities on the **observed** side only, because the namespace its declarations sit in is not one anything watches. Writing the alias is what brings the declaration back under judgement, and a wrong alias is reported.
- Drift stays silent about any kind nothing observes, and since [0056](../adr/0056-coverage-is-a-namespace.md) about any namespace nothing observes it in. The cost is the reverse case, now finer and therefore larger: uninstalling the only plugin that covers a namespace makes the report shrink rather than raise an alarm, so plugin health has to be watched somewhere else, through `changes` ([0038](../adr/0038-what-drift-may-say.md)).
- An estate whose declarations all sit in one namespace nothing observes gets an **empty declared half**, which is the correct answer and is indistinguishable from the report never running ([0056](../adr/0056-coverage-is-a-namespace.md)). Same shape as the restricted viewer case below.
- Coverage is inferred from what a plugin returned rather than what it is responsible for. It is no longer global: a kind is watched only in the namespaces something observed it in ([0056](../adr/0056-coverage-is-a-namespace.md)). Namespace is being asked to carry the meaning of scope, and nothing enforces that. It holds because plugins normalize at the edge and name what they read, so a plugin emitting one namespace across two clusters gets no benefit, and one giving every entity its own namespace makes the declared half silent for everything it touches. Ingester-declared coverage is still the fix, and still needs an interface that does not exist.
- A note closed with status done or dropped leaves the drift queue, so an orphaned note is no longer findable there once it is closed. `note` still returns it ([0045](../adr/0045-drift-is-a-maintenance-queue.md)).
- Observations are stored under a reserved `ingester:` scope that occupies the repository slot. Anything treating a repository as clonable, or as something a sweep can prune, has to check `index.IsObserved` first. The sweep got this wrong once and deleted every observation on its first pass.
- A rate limit is recognised and logged but not waited out. A sweep that exhausts the budget gives up until the next one rather than resuming when the limit resets. `changes` now says when that sweep is, so the wait is legible rather than invisible, which is not the same as shortening it ([0058](../adr/0058-a-read-time-is-a-fact-about-the-read.md)).

- **A repository the index knows and the controller does not is absent from `changes` entirely.** The durable read time rescues an entry whose in-memory time is missing; it cannot invent an entry. Right after a restart, before the first sweep finishes, the answer can under-report which repositories there are ([0058](../adr/0058-a-read-time-is-a-fact-about-the-read.md)).

- **A plugin whose process is dead reports no health, so its observations carry no age.** `Report` fills health only for a running plugin, and the observations it left behind are still being served. The line says it is not running, which is the more important half, but "how old is what this is still answering with" is unanswered exactly where it matters most ([0055](../adr/0055-supervising-plugin-processes.md), [0058](../adr/0058-a-read-time-is-a-fact-about-the-read.md)).

- **`changes` counts a repository with no entities as one with no `dusk.md`**, and the two are not the same. A non-participating repository is dropped from the controller's status altogether, so the third tally counts a participating repository that declares only notes. Nothing carries `Status.Participating` to the agent surface, which is the fact that would separate them.
- The viewport matrix is run by hand and nothing repeats it. It has now been run against a real catalog and passes, but a regression is caught only by somebody thinking to look ([0025](../adr/0025-responsive-ui.md)).
- A browser session is a bearer token in a cookie by another name: it grants the whole catalog and cannot be revoked short of rotating `DUSK_MCP_TOKEN`, which signs it. Signing in with GitHub narrows a view; it does not close this path ([0036](../adr/0036-deriving-what-a-viewer-sees.md)).
- Drift is **empty for every restricted viewer** under the default `DUSK_OBSERVED_VISIBLE_TO_ALL=false`. They can see no observation, so no kind is watched, and [0038](../adr/0038-what-drift-may-say.md) keeps drift silent where nothing watches. Correct, and it reads as a broken feature ([0051](../adr/0051-a-count-is-of-what-the-viewer-can-see.md)).
- Drift and integrity answer a **different question per viewer**. A relation or note pointing at something declared in a repository the viewer cannot read is reported to them as dangling, because [0036](../adr/0036-deriving-what-a-viewer-sees.md) answers invisible exactly as absent. The false positive is the price of not running an oracle for what exists elsewhere.
- The homepage's `reads` block still names every repository, and the overview's `declaring` count still counts them. Same class of leak as an unfiltered tally, in a block [0051](../adr/0051-a-count-is-of-what-the-viewer-can-see.md) did not cover.
- Notes are filtered by repository only inside the drift report. `search` still returns a note from a repository the viewer cannot read, on the reasoning that a note travels with the entity it is about, which does not survive [0051](../adr/0051-a-count-is-of-what-the-viewer-can-see.md).
- A page block's limit is applied before the viewer's filter, on the homepage and in `search` alike, so a restricted viewer's block can come back shorter than the limit it asked for rather than topped up.
- Nothing exercises the filtered reads over HTTP. `visibilityFor` reaches them through three handlers and `page.Resolve`, and the tests cover the index and the page, because standing up a signed-in browser session in a test needs a real OAuth exchange.
- Two API reads still answer a restricted viewer with refs they cannot open: `GET /api/entities/{ref}/dependents` walks the graph from any ref and filters nothing, and `GET /api/diff` renders a preview's changes the same way. Both are lists, so both want the `visible` predicate `search` and `entities` already use. Found while filtering the aggregates and left alone ([0051](../adr/0051-a-count-is-of-what-the-viewer-can-see.md)).
- **A restricted viewer holds an ordinary session, and the write half of the API does not ask who they are.** Forgetting an observation scope, installing or configuring a plugin, and invoking an action are gated on being signed in rather than on what the viewer can read. [0036](../adr/0036-deriving-what-a-viewer-sees.md) said sign-in narrows a view rather than securing a deployment; this is the sharpest edge of that.
- OAuth sign-in requests `repo` scope, which is far more than listing repository names needs. GitHub offers nothing narrower that still sees private repositories. A GitHub App ignores the scope entirely and grants what its installation permits, so this only bites a deployment pointed at a real OAuth App through the environment ([0036](../adr/0036-deriving-what-a-viewer-sees.md)).
- Identity sessions live in memory, so a restart signs everybody out. Every deploy is a restart, so this is routine rather than rare.
- A plugin's own output is kept in memory, bounded, and served per plugin, so anything its error string does not explain is readable without the pod. It survives a restart, because what a plugin printed as it died is the answer to why it died, but it still dies with Dusk.
- Events are a bounded in-memory buffer. Restarting loses what ran, so this is "what just happened" and not an audit trail, which is what [0015](../adr/0015-plugin-actions-and-events.md) accepts until a time-series exporter exists.
- An event records an actor, and over MCP that actor is always `agent`: the surface authenticates with one shared bearer token and has no per-caller identity. Two agents holding one token are indistinguishable in the record.
- A **plugin-scoped** action runs against the plugin's own configuration, because it names no entity to resolve an instance from. A plugin with several instances therefore cannot be told which one to create something in, and adding a flight to a second AirTrail would need the caller to name the instance.
- Approval is a confirmation flag on the call, not a queue somebody else can answer. An agent that cannot ask a human simply refuses, which is the right failure but not the same thing as an approval workflow.
- **The PVC now holds something not rebuildable from git.** Installed plugin binaries live in the data directory, which is what lets a restart need no network, and weakens a guarantee that was previously absolute and simple to explain ([0042](../adr/0042-installing-plugins.md)).
- A plugin instance observing a source Dusk cannot reach locally needs that source's credentials mounted into Dusk's pod. Observing a second Kubernetes cluster therefore means a kubeconfig secret, which is the case [0039](../adr/0039-one-plugin-transport.md) left open by rejecting network plugins. The cheaper shape is an authenticated push endpoint, and that decision has not been made.
- Being signed in and being let in are two decisions in two places: `access.Policy` guards the surface, `access.OAuth` holds the identity, and the policy only consults the identity because it was handed one through `Recognize`. Sign-in shipped without that call and silently bounced everybody back to the login page, so a new credential has to be taught to the gate as well as minted.
- Anything a login or setup page references has to be routed outside the gate that page exists to open. The favicon was not, so it redirected to `/login` and rendered nothing. There is no rule enforcing this beyond the tests that now cover it.
- A grid or flex item's automatic minimum is its **min-content** width, so `1fr` alone lets one long ref widen a column past the screen. Every track that holds catalog content wants `minmax(0, 1fr)`. This shipped in the single-column mobile rule while the two-column desktop rule had it right, which is why it was invisible on a laptop and broke every phone.
- Verifying a layout needs a viewport that is actually applied. Chrome headless `--window-size` lays out wider than it captures, so its screenshots crop rather than reflow and read as overflow that is not there. Measure `document.body.scrollWidth` against `clientWidth` in the page, and take screenshots through a browser whose `innerWidth` you have confirmed.
- Every open pull request holds a partition of the index, rebuilt on every push to its branch. Nothing prunes an abandoned one until it closes ([0037](../adr/0037-pull-request-previews.md)).
- A preview's drift and integrity are filtered for a restricted viewer like the default view's, but both are always asked at the default view rather than at the preview's ref, so a preview does not have drift or integrity of its own at all.

- A note update **merges over what the file says, except for `pinned`**, which is a bare bool on the way in and so cannot tell "leave it" from "unpin it". Changing a note's body silently unpins it. The fix is a tri-state on the input, the same shape a sensitive plugin field uses for "submitted empty means keep".
